# Call analysis

The admin dashboard at `/admin/call-analysis` automatically reviews retained ordinary calls and admin demo calls after completion. GPT-6 Sol uses the existing server-side OpenAI key, medium reasoning and strict structured output. Fourteen plain-language conversation checks cover resolution, frustration, repeated questions, tool failures, robotic repetition, broad-request clarification across every department, incorrect answers, products, offer conditions, unsupported claims, follow-ups, caller audio complaints and unresolved endings.

Twelve separate technical checks cover connection, packet loss, jitter, round-trip delay, concealment, buffering, response timing, tool errors, pipeline incidents, transcript capture, measured static/clipping/distortion and post-call processing. Application code calculates the whole-call result: one confirmed failure makes the call fail; missing required evidence produces Needs review. An unknown is never displayed as a green tick. Tool failures are counted once in the overall totals.

Select an item for its reason and evidence. The detail page exposes the original captured conversation with personal details redacted, and the existing recording when available. Generated assistant text does not certify playout, and a transcript or healthy network cannot rule out static. An abrupt text ending alone does not prove frustration or a premature hang-up. Today's catalogue is not proof of historical product or offer facts.

The reviewer paginates original `formatted_turn` journal events in sequence (including calls beyond the database’s 1,000-row response cap), verifies count continuity and both speakers, and rejects greeting-only readable dialogue as complete. It does not reconstruct missing speech from prompts, reasoning or summaries. Source dialogue is redacted before the API request. Failed answers require an excerpt in the strict response schema, and each quote is checked against the saved inputs. Requests use `store: false`, bounded output and retry limits. Reviews remain admin-only, retained for 30 days and erased with caller data.

Call-completion callbacks start analysis. A Supabase pg_cron/pg_net job retries every five minutes, using a dedicated encrypted Vault credential matched to the hidden dashboard `CALL_ANALYSIS_CRON_SECRET`. This avoids the current Vercel plan's daily-only scheduling restriction. Leases and fingerprints prevent duplicate requests; expired leases are retried with a bounded backoff. API credit exhaustion is an analysis error, not a failed customer call.

Version `2026-09-30.1` adds the expanded checklist and whole-call technical result. Older reviews show Needs update and are rerun individually rather than spending API credits on a bulk rerun.
