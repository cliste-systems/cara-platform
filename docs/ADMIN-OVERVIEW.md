# Admin overview

Calls and minutes use the current Europe/Dublin calendar day and include live, demo and engineer calls. Minutes are recorded duration divided by 60, not an invoice amount. Support inbox counts open support tickets; failed reviews count today’s failed analyses. Recent activity pages through today’s non-erased calls (Europe/Dublin calendar day), with capacity measured from the panel height; its total uses the same date bounds as the Calls metric. An out-of-range page resets automatically after midnight.

The authenticated overview endpoint refreshes on call events, with a ten-second fallback and focus/visibility refresh. Provider feeds remain on a separate one-minute cadence. Both panels have independent header pagination without footer counts or labels. Official provider feeds are fetched concurrently with a six-second timeout and 60-second Next fetch cache. The service registry is in `src/lib/admin-service-status.ts`; OpenAI uses the complete components feed (its summary truncates the list), others use Statuspage-compatible summary feeds. Never substitute a healthy result for missing/malformed feed data.

The panel covers the eight active integrations: Supabase, Vercel, LiveKit, Twilio, OpenAI, Stripe, Resend and Cloudflare. ElevenLabs and OpenRouter are excluded per the confirmed active stack. Sentry is not configured; AssemblyAI, Deepgram and Cartesia are not part of the active GPT Live route and are excluded. Each provider has an explicit product/component allowlist in SERVICE_COMPONENTS. Supabase compute is eu-central-1 (verified project region), Vercel is dub1 (vercel.json), LiveKit is Europe Central (worker deployment contract), and Twilio voice/SIP is IE1. Cloudflare includes Authoritative DNS, DNS Updates and Turnstile; OpenAI includes Realtime and Responses. Monitoring details are displayed for each provider. Vendor-wide aggregate status is ignored. Incidents must match a selected component; irrelevant carrier geography and MMS incidents are excluded. Missing matching components stay Unknown, never green. These are scoped provider reports, not direct account availability probes. Active maintenance is distinct from degradation/outage. There are no paid monitoring subscriptions or background notification jobs.

Active calls come from usage_records where ended_at is null. A completed call with the same room/call SID replaces the active row without duplication. The admin SSE route relays Supabase Realtime usage_records/call_logs invalidations after the existing MFA gate, without sending raw event data or server credentials. Streams reconnect after 55 seconds to recheck the session and clean up subscriptions; tenant RLS is unchanged. A new call returns Recent activity to its first page.

Database feeds use service-role-only admin_overview_feeds with SQL pagination; totals use service-role-only `admin_overview_snapshot` (migration `20260928165533_admin_overview_snapshot.sql`). The endpoint requires the existing admin MFA session; vendor feeds and credentials are fetched only on the server.

## Non-billable demo calls

Demo calls do not create usage_records. They now use admin_live_call_sessions, a service-role-only RLS table: room creation registers an inactive session, the connected browser reports presence immediately and every 15 seconds, and disconnect/end/pagehide marks it ended. A late heartbeat cannot reopen a terminal session. Missing heartbeats expire from the live feed after 90 seconds; the retention sweep deletes presence rows older than 24 hours. The presence endpoint validates the admin MFA session and request origin; recovery for older active rooms checks their LiveKit metadata. Realtime changes on this table invalidate the overview alongside usage_records and call_logs. Completed call records deduplicate by room name.

Verification: exercised the presence endpoint against a real temporary LiveKit room, checked inclusion in the overview RPC, ended it, and confirmed a delayed heartbeat did not revive it. No usage/billing record was created. Temporary room and presence row were removed. This covers the non-billable path that the earlier usage-record smoke test missed.
